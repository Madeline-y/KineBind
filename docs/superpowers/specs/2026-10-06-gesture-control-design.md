# KineBind V0.1：学习新手势并绑定鼠标指令

日期：2026-10-06。规格来自本轮对话和已确认的第一版细节。当前仅完成规格整理，学习、识别和鼠标控制尚未实现。发布到项目 Issue 时使用标签 `ready-for-agent`。

## Problem Statement

用户已经能通过 XIAO nRF52840 Sense 采集六轴数据，也确认了一轮记录包含 5 次“左挥”。目前只能查看波形和人工分析，尚不能把个人示范保存为可复用手势，再让新动作触发电脑指令。

用户希望用“左挥”打通完整流程：命名一个动作、逐次示范、检查样本、学习、绑定电脑指令、主动开启识别、用动作控制鼠标，并能随时停止。新增手势应复用同一流程。

“左挥”按用户定义，是“向左挥动 → 向右回收到起始位置”的完整组合。一次完整往返算一个手势，回收属于同一手势。第一版允许自然的快慢变化及小幅握姿偏差，使用同一只手、相近握法和起始朝向。

## Solution

提供一个 Windows 本地简单窗口，使用 USB 接收六轴数据，由 Python 完成示范管理、模板匹配和电脑动作执行。

用户输入手势名称，每次点击开始录制，经过 3 秒倒计时后做一个完整动作，再手动结束。窗口显示曲线供检查、保存或重录，累计保存 5 个独立样本。随后采集约 30 秒非目标动作，用于校准拒绝阈值。学习完成后保存模板及绑定，重启后可加载。

首个绑定为：每识别到一次完整“左挥”，鼠标指针向左移动 100 像素，纵向位置不变。到达桌面边缘时按合法范围截断位移。

用户点击“开始识别”后才允许执行鼠标动作；点击“停止”后不再执行。完整回收被识别后立即触发，不额外等待 0.5 秒停稳。采用保守的接受条件，不确定的动作不执行；一次手势只执行一次。

## User Stories

1. 作为用户，我希望为自己示范的动作命名，以便用自己的动作定义手势。
2. 作为用户，我希望“左挥”包含左挥和回收，以便一个完整往返只对应一次指令。
3. 作为用户，我希望通过 USB 使用已有设备，以便直接利用目前已验证的采集链路。
4. 作为用户，我希望选择实际串口并看到连接状态，以便端口变化时仍能使用设备。
5. 作为用户，我希望每次只录入一个完整动作，以便检查每个样本的范围。
6. 作为用户，我希望开始录制前有 3 秒倒计时，以便准备握姿和动作。
7. 作为用户，我希望手动结束录制，以便完整保留回收阶段。
8. 作为用户，我希望录制后查看六轴曲线，以便判断动作是否录完整。
9. 作为用户，我希望能调整样本的起止边界，以便去掉多余静止并保留完整组合。
10. 作为用户，我希望单独保存或重录每个样本，以便修正一次不满意的示范。
11. 作为用户，我希望清楚看到已保存的 5 个样本，以便知道学习准备是否完成。
12. 作为用户，我希望可以自然地改变示范速度，以便不必机械地重复完全相同的动作。
13. 作为用户，我希望采集约 30 秒非目标动作，以便系统学习哪些移动应该忽略。
14. 作为用户，我希望看到学习或校准效果不佳的提示，以便补充更合适的样本。
15. 作为用户，我希望保存手势模板和绑定，以便关闭程序后无需重新录入。
16. 作为用户，我希望新增手势复用同一录入流程，以便不用为每个新手势修改识别代码。
17. 作为用户，我希望把左挥绑定为鼠标左移 100 像素，以便直观看到完整流程的结果。
18. 作为用户，我希望电脑动作与手势模板分开配置，以便调整绑定时保留已录示范。
19. 作为用户，我希望点击“开始识别”才启用控制，以便自主决定何时使用手势。
20. 作为用户，我希望点击“停止”后立即停用控制，以便停止后鼠标不再受程序影响。
21. 作为用户，我希望完整回收被识别后就触发，以便获得及时反馈。
22. 作为用户，我希望中间停顿和单独回收不被计作新手势，以便避免提前或重复执行。
23. 作为用户，我希望不确定的动作被忽略，以便优先减少误触发。
24. 作为用户，我希望看到识别结果和执行结果，以便分辨漏识别与执行失败。
25. 作为用户，我希望断开设备或关闭窗口时停止执行，以便旧数据不会继续控制鼠标。
26. 作为用户，我希望用新一轮动作检查效果，以便知道模板能否识别新的示范。

## Implementation Decisions

- **沿用采集链路。** 使用现有八字段协议、设备时间戳、序号检查和六轴单位。默认 COM7、115200，端口可选择；USB 输出目标约 50 Hz。现有 Python 环境与原始采集记录继续使用。
- **通用的手势数据。** 手势具有稳定 ID、名称、5 个已确认样本、非目标记录、模板、处理参数、阈值、绑定和版本信息。新增名称与示范通过数据配置接入，不写固定某一轴的波峰规则。第一版可选择一个已学习手势进行识别，不要求同时分类多个手势。
- **逐次录入与检查。** 倒计时阶段不计入动作样本；录制开始后到用户手动结束之间保留原始数据。检查界面支持设置有效起止时间，保留动作内部停顿。空样本、时间异常或明显削顶应提示重录，不能悄悄替换原始记录。
- **六轴模板学习。** 采用受约束的多维 DTW，保留 5 条独立模板及持续时间。平滑、时间采样处理和通道缩放在学习、回放和实时识别中一致，并随模板保存。加速度与角速度采用一致的固定尺度，保留幅度信息，限制过度时间变形。
- **保守的阈值校准。** 用不同示范之间的匹配距离以及非目标候选窗口的距离确定接受阈值；不能用样本与自身匹配的零距离作为依据。校准效果不佳时显示具体状态，允许补录或重录。距离不能直接显示为识别概率。
- **完整动作判断。** 实时窗口有界，候选范围参考运动开始和已录模板的持续时间。只有完整六轴波形及末段回收特征符合模板，才产生事件。左挥前半段、中间停顿、单独回收不应触发。完成判断不依赖固定 0.5 秒停稳等待；实际检测和执行延迟需记录。
- **单次执行。** 一个事件包含会话 ID、事件 ID、手势 ID、动作时间区间及匹配距离。已执行区间被记录和消费，滑动窗口对同一次动作的重复匹配不能再次执行。下一次独立完整动作可再次触发；固定冷却时间不能作为唯一的去重方法。
- **显式启停。** 程序启动、录入和检查样本期间默认停用鼠标执行。只有已加载可用模型、设备正常且用户点击开始识别后，才启用执行。停止使当前会话失效、丢弃待执行事件并清空候选；异步线程必须在执行前核对会话和启用状态，防止停止后的旧事件继续执行。重新开始使用新会话，不自动恢复旧动作。
- **一次串口连接。** 采样来源独立于模式；录入和识别共享同一串口连接，窗口保持响应。模式不能同时录入和控制鼠标。断开、设备重启或数据时间异常时结束识别并提示，重新连接后需用户主动开始。
- **分离识别与执行。** 识别输出事件，执行器依据绑定处理。首个动作类型仅为固定向左移动鼠标；修改该绑定无需重新录入手势。执行成功或失败作为可见结果记录，失败事件不盲目重试，以免造成重复位移。
- **鼠标位移。** 使用 Windows 指针位置接口，读取当前坐标，目标横坐标减少 100，纵坐标保持不变。使用一致的屏幕像素坐标约定，处理可用桌面边界并检查返回结果。动作无需依赖记事本是否在前台；程序只移动鼠标指针。
- **简单窗口。** 提供命名、串口状态、倒计时、样本进度、曲线检查、保存/重录、非目标录制、学习状态、绑定选择、开始识别/停止及最近事件结果。
- **持久化与记录。** 保存原始示范和有效边界、非目标样本、模板、处理参数、校准结果及绑定；重启后可选择加载。未确认的新录制不改变已有可用手势。识别日志区分匹配被拒绝、接受、执行失败、重复事件被忽略和会话停止。

## Testing Decisions

### 测试边界

主要自动测试边界为完整应用流程：从录入和控制命令、六轴数据输入，到可见录入状态、识别事件和鼠标执行结果。复用现有可替换串口数据源的方式，增加数据回放和鼠标执行替身；优先从这一高层边界验证外部行为。

现有测试已经通过替换串口来源检查 CSV 保存、断开后的关闭、旧固件提示和文件保护。新测试沿用这一实践，避免为每个内部函数增加新的测试接口。自动测试不移动真实鼠标；另做实板与实际指针位置的验收。

不检查内部类结构、特定循环次数或精确 DTW 路径。算法参数通过业务效果验证；必要的时间与执行依赖可受控，用于复现倒计时、连续窗口和停止时待处理事件。

### 可观察的验收行为

1. 完成命名、3 秒倒计时、手动录制结束、曲线检查和保存/重录；累计得到 5 个独立有效示范。倒计时不混入样本。
2. 录入约 30 秒非目标动作后生成校准结果；效果不佳时能重录，不能显示为已成功学会。
3. 保存并重启后恢复手势和绑定；添加另一手势名称仍可使用同一录入流程。
4. 回放完整已标注左挥，得到一个完整动作事件；前半段、中间停顿、单独回收以及重复窗口不产生额外执行。
5. 程序启动、录入、检查和停止状态下，即使输入匹配动作也不执行鼠标指令。
6. 点击开始后，完整左挥产生一次鼠标左移请求；纵向位移为零。边缘时截断，正常位置目标位移为 100 像素。
7. 模拟已有待执行事件时点击停止，停止生效后该事件不能再执行；重新开始不能执行上一会话事件。
8. 断开、重启或无效时间序列使识别停用；重新连接后不会自动控制鼠标。
9. 执行失败可见且不会自动重复移动；测试从事件到执行的结果，不仅检查识别名称。
10. 用另一轮新采集动作评估快慢变化，记录漏识别、误触发、提前触发、重复触发及实测响应延迟。训练数据不能兼作最终验收数据。
11. 实板验收由用户开启识别，完成组合并观察真实鼠标移动；停止后再做动作，鼠标不受程序控制。核对鼠标起止坐标与日志。

本轮提出的高层测试边界已向用户展示，测试范围若有调整意见再更新本文。此前讨论的 9/10、200 毫秒以及“非目标移动 2 分钟零误触发”均不列为用户已确认的硬性验收门槛。优先减少误触发和完整动作单次执行仍是第一版要求。

## Out of Scope

- BLE、独立电池供电、板端学习与识别、TinyML 和神经网络训练。
- 任意换手、任意板子朝向或大幅改变握法后的识别保证。
- 挥动幅度与鼠标距离成比例、连续空中鼠标、鼠标点击、拖拽和键盘快捷键。
- 根据前台软件改变指令、后台自动启用、系统常驻和开机启动。
- 同时识别多个手势及其冲突处理；第一版支持逐个学习、保存、选择和使用。
- 全自动分割训练录制、自动结束录制和免人工检查样本。
- 全套多屏布局兼容性验收；实现仍须遵守统一坐标和合法桌面边界。
- 以未确认的波形峰数当作训练标注或识别准确率。
